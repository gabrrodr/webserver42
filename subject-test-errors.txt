	- GET sometimes works, but other times it closes the socket too early, possibly due to:
		- a threading or forking issue(one handler killing the connection too soon)
		- a race condition where the socket is closed before the response is sent
		- handling a second request on a reused socket improperly(e.g. if it's HTTP/1.1 and the test expects Keep-Alive)

	- Possible fixes:
		- add to header: "Connection: close\r\n";
			while adding this to the header might make sense in some cases, it
			probably will need more aproaches
		- close the socket only when the full response has been sent somehow?
		  not sure how to see if the connection to the socket is still neeeded
		  but maybe that can work
